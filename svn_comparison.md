# Git vs SVN — сравнение

## 1. Почему в Git ветвление "дешёвое", а в SVN — "дорогое"?

В Git ветка — это просто указатель (ссылка) на конкретный коммит, 
её создание занимает доли секунды и не требует копирования файлов. 
В SVN ветка технически реализована как полная копия директории 
проекта на сервере, поэтому создание ветки — это реальное копирование 
всех файлов, что занимает время и место, особенно в больших проектах.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, нельзя. SVN — централизованная система: у разработчика на компьютере 
хранится только рабочая копия файлов, а вся история изменений и репозиторий 
находятся на одном центральном сервере. Коммит в SVN — это отправка изменений 
напрямую на сервер, поэтому без подключения к нему закоммитить невозможно. 
В Git же у каждого разработчика есть полная копия репозитория локально, 
поэтому коммитить можно офлайн, а синхронизация с сервером (push/pull) 
происходит отдельным действием.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты, изначально построенные на SVN (переход на Git дорог и рискован).
- Компании с жёсткими требованиями к централизованному контролю доступа 
  (например, госсектор, банки), где важно, чтобы вся история хранилась 
  в одном контролируемом месте.
- Работа с очень большими бинарными файлами — SVN исторически проще 
  настраивается для хранения больших нефрагментированных файлов 
  (хотя сейчас для этого чаще используют Git LFS).
- Команды, где не нужна сложная параллельная разработка в ветках, 
  а важна простая линейная история изменений.
